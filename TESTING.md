# VolleyCore Architecture

## Technology

- Frontend: Static HTML, CSS and JavaScript
- Hosting: Netlify
- Authentication: Firebase Authentication
- Database: Cloud Firestore
- Storage: Not enabled

## Environments

- `main` -> production -> `volleycore.netlify.app`
- `develop` -> testing -> Netlify branch deploy

## Core modules

- Authentication
- Users
- Families
- Players
- Categories
- Training schedules
- Events
- Venues
- Charges and payments
- SINPE reports
- Announcements
- Link requests
- Reports

## Family model

A family is an independent business entity. It is not calculated from the number of registered users.

```text
Family
├── memberUserIds[]
└── playerIds[]
```

### Official identification

- Internal document ID generated by Firestore
- Visible code: `FAM-0001`
- Editable display name, for example: `Familia Vargas Molina`

### Rules

- Several users may belong to one family.
- Several players may belong to one family.
- A user may not create a new family when linking to a player who already belongs to one.
- Duplicate families must be mergeable without deleting historical data.
- A merged family is marked `status: merged` and keeps `mergedInto`.

## Player-category model

A player may belong to multiple categories.

```text
primaryCategoryId: string
categoryIds: string[]
```

The primary category is used for the default administrative and financial context. Other categories provide access to training schedules, events, calendars and announcements.
